# RESUELVE — MANUAL DE MARCA v1.0

**Versión:** 1.0  
**Fecha:** septiembre 2026  
**Marca:** Resuelve  
**Producto:** marketplace local de servicios + herramientas de gestión para profesionales  
**Mercado inicial:** Tandil, Buenos Aires  
**Estado:** identidad base para producto digital, comunicación, redes y crecimiento comercial

---

# 1. Propósito del manual

Este documento define cómo debe verse, sonar y comportarse **Resuelve**.

No es solo un manual de logo. Es un sistema de marca para que:

- la web se vea profesional;
- el producto deje de parecer una plantilla genérica de SaaS;
- cliente y profesional reconozcan la misma marca en cada pantalla;
- diseño, desarrollo y marketing puedan trabajar con criterios comunes;
- la identidad pueda crecer sin depender de decisiones visuales improvisadas.

La prioridad de Resuelve no es “verse tecnológica”.

La prioridad es transmitir:

> **confianza, claridad, oficio y resolución.**

La tecnología tiene que sentirse en la experiencia, no en una estética futurista.

---

# 2. Qué es Resuelve

Resuelve conecta personas que necesitan resolver un trabajo con profesionales locales que pueden hacerlo.

Para el cliente:

> **Encontrar, comparar y elegir a quién confiarle un trabajo.**

Para el profesional:

> **Conseguir oportunidades y administrar solicitudes, presupuestos y trabajo desde un solo lugar.**

Resuelve combina dos lógicas:

- **marketplace de servicios** para clientes;
- **herramienta de trabajo / SaaS** para profesionales.

La marca debe poder hablarle a ambos sin parecer dos productos distintos.

# 3. Posicionamiento

## 3.1. Posicionamiento central

> **Resuelve hace más simple encontrar y contratar profesionales locales, con información clara para decidir y herramientas concretas para trabajar mejor.**

## 3.2. Territorio de marca

Resuelve vive en la intersección de:

- hogar;
- oficio;
- cercanía;
- confianza;
- decisión;
- organización;
- trabajo real.

No pertenece visualmente al mundo de:

- fintech;
- crypto;
- software corporativo;
- delivery;
- redes sociales;
- “AI startup”.

## 3.3. Diferencial perceptual

La marca debe sentirse como:

> **una herramienta moderna hecha para problemas reales.**

No como:

> “otra plataforma digital llena de dashboards y promesas”.

---

# 4. Esencia de marca

## 4.1. Idea central

# **Resolver da tranquilidad.**

Resuelve existe para reducir incertidumbre.

Un cliente no entra porque quiere “usar una plataforma”.

Entra porque:

- tiene una pérdida;
- necesita un electricista;
- tiene que mudarse;
- se le rompió algo;
- necesita resolverlo.

Un profesional tampoco entra porque quiere “gestionar leads”.

Entra porque:

- quiere trabajo;
- necesita ordenar pedidos;
- quiere cotizar rápido;
- necesita saber qué aceptaron;
- quiere coordinar mejor.

Toda decisión de marca debe ayudar a bajar fricción y aumentar claridad.

# 10. Sistema de logo

La identidad actual del producto ya tiene una buena base:

- símbolo de check;
- contenedor verde;
- wordmark “Resuelve”.

Ese concepto debe conservarse y profesionalizarse.

## 10.1. Significado del símbolo

El check representa:

- decisión;
- tarea encaminada;
- confianza;
- “esto se resolvió”.

No representa “éxito tecnológico” ni gamificación.

## 10.2. Composición principal

```text
[ símbolo check ]  Resuelve
```

Uso recomendado:

- header;
- landing;
- documentos;
- redes;
- publicidad.

## 10.3. Símbolo aislado

Puede usarse solo en:

- favicon;
- avatar de marca;
- app icon / PWA;
- loading branded;
- pequeños espacios donde el nombre ya es evidente.

No usarlo repetidamente como decoración dentro del producto.

## 10.4. Wordmark transitorio

Hasta realizar lettering propio, usar:

**Archivo Bold 700**

Características:

- `font-weight: 700`;
- tracking aproximado: `-0.025em`;
- nunca italic;
- nunca uppercase completa.

El objetivo futuro puede ser dibujar un wordmark personalizado basado en Archivo, pero no es requisito para lanzar.

# 20. Tipografía — nueva dirección

La tipografía actual se siente demasiado cercana a la estética habitual de productos generados con templates/IA.

La nueva dirección debe tener:

- personalidad;
- excelente lectura;
- seriedad;
- calidez;
- buena performance digital.

## Sistema recomendado

# **Source Serif 4 + Archivo**

### Source Serif 4
Uso:

- H1;
- titulares editoriales;
- claims de marca;
- campañas;
- landing;
- momentos de decisión/importancia.

Aporta:

- carácter;
- confianza;
- humanidad;
- una sensación más estable y menos “startup”.

### Archivo
Uso:

- UI;
- body;
- labels;
- botones;
- formularios;
- tablas;
- precios;
- navegación.

Aporta:

- claridad;
- eficiencia;
- excelente densidad;
- tono profesional;
- buena lectura en desktop y mobile.

---

# 21. Por qué esta combinación

No buscamos “una serif elegante”.

Buscamos contraste entre:

> **voz humana + herramienta práctica.**

Source Serif 4 da carácter a la marca.

Archivo mantiene la interfaz rápida y clara.

Ejemplo conceptual:

```text
Source Serif 4
Pérdida bajo mesada

Archivo
Plomería · Villa Italia · Hoy, 19:30
```

El resultado se siente editorial y confiable sin volverse antiguo.

# 23. Reglas tipográficas

## Titulares

- usar sentence case;
- no usar mayúsculas completas;
- tracking levemente cerrado;
- máximo 2 líneas cuando sea posible.

## Body

- ancho de lectura ideal: 55–75 caracteres;
- evitar párrafos largos dentro de cards;
- preferir estructura y bullets cuando ayuda.

## Precios

Usar Archivo con:

```css
font-variant-numeric: tabular-nums;
```

Ejemplo:

`$ 300.000`

No hacer el símbolo `$` más grande que el monto.

## Datos / IDs

Usar Archivo.

No introducir monospace salvo:

- códigos;
- IDs técnicos;
- documentación interna.

# 29. Inputs

Los inputs deben sentirse de producto profesional.

Características:

- 48–52 px de alto;
- label siempre visible;
- border neutro;
- focus Forest;
- error danger;
- ayuda debajo cuando sea necesaria.

No usar placeholder como label.

No llenar formularios de iconos decorativos.

---

# 30. Cards

Una card tiene que existir por una razón.

Usarla cuando:

- agrupa información;
- es seleccionable;
- tiene estado propio;
- necesita separarse físicamente.

No envolver cada sección en una card blanca.

La pantalla debe conservar aire y fondo crema visible.

---

# 31. Status chips

Los chips deben describir estado, no decorar.

Ejemplos válidos:

- Nueva
- Presupuesto enviado
- Aceptado
- No elegido
- Urgente
- Matrícula verificada

Evitar:

- 5 chips simultáneos en una card;
- etiquetas que repitan texto visible;
- pills para metadata común.

---

# 46. Motion

Resuelve debe moverse con calma.

Duraciones:

```text
120–180 ms  microinteracciones
180–240 ms  dropdown / modal
240–320 ms  cambios de vista suaves
```

Curva sugerida:

```css
cubic-bezier(.2,.8,.2,1)
```

Usar movimiento para:

- confirmar acción;
- orientar;
- mostrar estado.

No usar para decorar.

Siempre respetar:

`prefers-reduced-motion`.
